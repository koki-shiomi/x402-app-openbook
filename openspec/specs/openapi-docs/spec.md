# openapi-docs Specification

## Purpose
有料 API のうち利用者向けのエンドポイントを OpenAPI 形式で記述し、機械可読な形と人間が読める画面の双方で、支払いなしで参照できるようにする。API の使い方を文章だけに頼らず、標準形式のツールで確かめられる状態を保つ。

## Requirements

### Requirement: ドキュメントの対象範囲

システムは、利用者向けのエンドポイントのみを OpenAPI ドキュメントに含めなければならない（SHALL）。運営者専用のエンドポイントと稼働確認用のエンドポイントを含めてはならない（MUST NOT）。

利用者向けの API ドキュメントに運営者向けエンドポイントを含めてはならないという既存の制約は、OpenAPI ドキュメントにも同様に適用される。

#### Scenario: 利用者向けエンドポイントの記載

- **WHEN** OpenAPI ドキュメントを参照する
- **THEN** `GET /v1/records` と `GET /v1/records/{date}` の定義が含まれる

#### Scenario: 運営者向けエンドポイントの除外

- **WHEN** OpenAPI ドキュメントを参照する
- **THEN** 手動再実行と稼働確認のエンドポイントの定義は含まれない

### Requirement: 決済プロトコルの意味論を複製しない

システムは、OpenAPI ドキュメントに決済の要求・応答の形（スキーマ）を記述しなければならない（SHALL）。決済プロトコルの意味論（署名の組み立て方、EIP-712 のドメインの決定方法、事前に必要な預け入れの手順など）を記述してはならない（MUST NOT）。これらは既存の文書への参照に留めなければならない（SHALL）。

同じ意図を複数の文書に重複して記載すると、一方を更新した際にもう一方が古いまま残る。決済の意味論は `paid-record-api` と `x402-payment` 仕様がすでに定めており、OpenAPI ドキュメントはインタフェースの形を示す役割に限る。

#### Scenario: 402 応答の形の記載

- **WHEN** `GET /v1/records/{date}` の OpenAPI 定義を参照する
- **THEN** 402 応答のスキーマ（`PAYMENT-REQUIRED` ヘッダの中身）が記載されている

#### Scenario: 決済手順の非重複

- **WHEN** OpenAPI ドキュメントを参照する
- **THEN** 署名の組み立て方や事前の預け入れ手順は記載されておらず、既存の文書への参照のみが示される

### Requirement: ドキュメントの配信

システムは、OpenAPI ドキュメントを `GET /openapi.json` で、支払いを求めずに配信しなければならない（SHALL）。

#### Scenario: ドキュメントの取得

- **WHEN** 支払いを伴わずに `GET /openapi.json` を要求する
- **THEN** OpenAPI ドキュメントが返る

### Requirement: 閲覧用の画面

システムは、OpenAPI ドキュメントを人間が読める形で表示する画面を `GET /docs` に置き、支払いを求めずに表示しなければならない（SHALL）。画面は `GET /openapi.json` の内容を読み込んで表示しなければならない（SHALL）。

ドキュメントの内容を画面に複製すると、`GET /openapi.json` を更新した際に画面側が古いまま残る。画面は常に配信中のドキュメントを読み込むことで、二重管理を避ける。

#### Scenario: 画面の表示

- **WHEN** 支払いを伴わずに `GET /docs` を要求する
- **THEN** OpenAPI ドキュメントの内容を表示する画面が返る

#### Scenario: 配信中のドキュメントの反映

- **WHEN** `GET /openapi.json` の内容を更新する
- **THEN** `GET /docs` の画面は複製した内容ではなく、更新後の `GET /openapi.json` を読み込んで表示する

### Requirement: 発見レイヤーへの非掲載

システムは、x402 の発見レイヤー（Bazaar など）への登録を行ってはならない（MUST NOT）。

本システムが用いる決済の取次（Circle の hosted facilitator）は、主要な発見レイヤーが要求する取次と異なり、掲載の要件を満たさない。無理に適合させると、取次の選定が発見レイヤーへの掲載可否に左右されることになる。

#### Scenario: 発見レイヤーへの登録の不在

- **WHEN** システムの実装を確認する
- **THEN** x402 の発見レイヤーへ登録する処理は存在しない
