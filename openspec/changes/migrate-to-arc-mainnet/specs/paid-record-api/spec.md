## MODIFIED Requirements

### Requirement: 取得可能な日付の一覧

システムは、取得可能な対象日の一覧を支払いなしで提供しなければならない（SHALL）。一覧には対象日とそのリビジョン番号のみを含め、金額を含めてはならない（MUST NOT）。

一覧の対象は、レコードが存在し、かつ最新リビジョンが刻印済みの日とする。取得できない日を一覧に含めてはならない（MUST NOT）。刻印済みかどうかは、レコードの最新リビジョンと刻印済みの最新リビジョンを突き合わせて判定しなければならない（SHALL）。刻印が 1 件でも存在することをもって刻印済みと見なしてはならない（MUST NOT）。

一覧が示すリビジョン番号は、その日を取得したときに返るリビジョン番号と一致しなければならない（SHALL）。

移行後の公開対象はメインネットで刻印したレコードのみとし、削除した旧開発データを一覧に含めてはならない（MUST NOT）。旧データを除去してメインネット専用として再開するため、テストネットのレコードとの混在や動的なチェーン別の一覧は提供しない。

訂正リビジョンが追加されてから刻印されるまでの間、その日はレコードの最新リビジョンだけが未刻印で、それより前のリビジョンは刻印済みである。刻印の有無だけで判定すると、この状態の日を取得できると誤って示し、示すリビジョン番号も実際に返るものと食い違う。

金額を含めないのは、一覧が有料の対象である日次レコードの代替にならないようにするためである。一覧を無料にするのは、利用者が存在しない日や刻印待ちの日に支払うことを防ぎ、取得する前に対象を選べるようにするためである。

#### Scenario: 一覧の取得

- **WHEN** 支払いを伴わずに一覧を要求する
- **THEN** 取得可能な対象日とそのリビジョン番号が返り、金額は含まれない

#### Scenario: 未刻印の日の除外

- **WHEN** レコードは存在するが未刻印の日がある状態で一覧を要求する
- **THEN** その日は一覧に含まれない

#### Scenario: 訂正リビジョンが未刻印の日の除外

- **WHEN** ある日のレコードに訂正リビジョンが追加され、そのリビジョンがまだ刻印されていない状態で一覧を要求する
- **THEN** その日は一覧に含まれない。刻印済みの古いリビジョン番号で一覧に現れることはない

#### Scenario: 刻印後の再掲

- **WHEN** 訂正リビジョンが刻印された後に一覧を要求する
- **THEN** その日が一覧に現れ、リビジョン番号は訂正後のものである

#### Scenario: 一覧のリビジョン番号と取得結果の一致

- **WHEN** 一覧に現れた日を取得する
- **THEN** 返るレコードのリビジョン番号は、一覧が示していた番号と一致する

#### Scenario: 開発データの削除後の一覧

- **WHEN** 旧開発データを削除した後、最初のメインネットのレコードが刻印される前に一覧を要求する
- **THEN** 空の一覧が返り、旧開発期間の対象日は含まれない

#### Scenario: メインネットでの刻印後の一覧

- **WHEN** 再開後のレコードの最新リビジョンがメインネットで刻印される
- **THEN** その日とリビジョン番号が一覧に現れ、削除した旧開発期間の日は現れない

## ADDED Requirements

### Requirement: 移行前の開発データの取得

システムは、移行時に削除した旧開発データの対象日を取得しようとする要求に、支払いを求めず HTTP 404 を返さなければならない（SHALL）。旧データを保存・復元して返す手段は提供しない。

#### Scenario: 削除した旧対象日の要求

- **WHEN** 移行時に削除した旧開発データの対象日を要求する
- **THEN** 支払いを求められず、HTTP 404 が返る

### Requirement: メインネットでの決済と検証

システムは、移行後の日次レコードについて、Arc メインネット（`eip155:5042`）の USDC で支払いを要求しなければならない（SHALL）。価格は 0.10 USDC とする。決済条件は本番 facilitator が広告する対象ネットワークの条件と一致しなければならない（SHALL）。

画面からの残高照会・預入れ・支払いの署名は、メインネットの資産と Gateway Wallet に対して行わなければならない（SHALL）。取得したレコードの検証は公開設定にあるメインネットのコントラクトを根拠とし、API の自己申告だけを根拠にしてはならない（MUST NOT）。

#### Scenario: メインネットの支払い条件

- **WHEN** 再開後の刻印済みの日を支払いなしで要求する
- **THEN** 本番 facilitator の条件に沿った `eip155:5042` の USDC 0.10 の支払い条件が返る

#### Scenario: 画面からの預入れと購入

- **WHEN** 利用者が画面から決済用残高を照会し、必要に応じて預け入れてレコードを購入する
- **THEN** メインネットの Gateway Wallet と署名条件を使用し、決済成立後にレコードと検証結果が表示される

#### Scenario: 取得したレコードのメインネット検証

- **WHEN** 保存されたバイト列を取得して、その SHA-256 を公開設定のメインネットの刻印と照合する
- **THEN** ハッシュが一致し、検証はチェーン ID `5042` と公開したコントラクトに基づく
