## ADDED Requirements

### Requirement: 刻印先のチェーンの設定

システムは、刻印先のチェーン（チェーン ID・RPC の所在・コントラクトのアドレス）を設定として持たなければならない（SHALL）。チェーンに依存する値を実装へ固定で埋め込んではならない（MUST NOT）。

送信の前にチェーン ID を照会し、設定したチェーン ID と一致しない場合は送信してはならない（MUST NOT）。

刻印先を移す際に、実装へ散らばった固定値を取りこぼすと、一部が旧いチェーンを向いたまま残る。照会と送信が別のチェーンを向くと、刻印済みの判定が成立しないまま送信を繰り返すことになる。

#### Scenario: 設定したチェーンへの送信

- **WHEN** 設定したチェーン ID と、接続先の RPC が返すチェーン ID が一致する
- **THEN** 刻印が送信される

#### Scenario: 設定と接続先の不一致

- **WHEN** 設定したチェーン ID と、接続先の RPC が返すチェーン ID が異なる
- **THEN** 刻印は送信されず、不一致が実行記録に残る

### Requirement: 設定したチェーン以外で刻印された日の扱い

システムは、現在設定しているチェーン以外で刻印された対象日を、刻印済みとして扱ってはならない（MUST NOT）。

刻印の記録はチェーン ID を持つ。刻印先を移した後、過去の刻印は移行前のチェーンを指したままになる。これを刻印済みとして扱うと、現在の設定では検証できない日を公開することになり、「公開するすべての情報が検証可能である」という前提が崩れる。

#### Scenario: 移行前のチェーンで刻印された日

- **WHEN** 現在の設定と異なるチェーン ID を持つ刻印の記録がある対象日を扱う
- **THEN** その日は刻印済みとして扱われない

## MODIFIED Requirements

### Requirement: 署名鍵の扱い

システムは、刻印専用の署名鍵を用いなければならない（SHALL）。署名鍵は Worker のシークレットとしてのみ保持し、実行記録・生応答・刻印の結果に含めてはならない（MUST NOT）。

署名鍵・RPC の URL・コントラクトのアドレスのいずれかが未設定の場合、システムは刻印を行わず、未設定の項目名を実行記録に残さなければならない（SHALL）。この場合も収集は通常どおり行う。

刻印専用とするのは、鍵が漏洩したときに失うものを、刻印の書き込み権限と、この鍵が保有する資産だけに限るためである。**この鍵は実際の価値を持つ資産を扱う。**保有させる額は、刻印を続けるのに要する分に留めなければならない（SHALL）。決済の受け取りに用いる額をこの鍵へ集めてはならない（MUST NOT）。

#### Scenario: 署名鍵が未設定

- **WHEN** 署名鍵が設定されていない状態で日次実行を行う
- **THEN** レコードは保存され、刻印は行われず、未設定の項目名が刻印の実行記録に残る

#### Scenario: 実行記録への署名鍵の混入

- **WHEN** 刻印の実行記録を保存する
- **THEN** 記録に署名鍵の値は含まれない
