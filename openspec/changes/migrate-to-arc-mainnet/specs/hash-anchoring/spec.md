## ADDED Requirements

### Requirement: 刻印先のチェーンの設定

システムは、刻印先のチェーン（チェーン ID・RPC の所在・コントラクトのアドレス）を設定として持たなければならない（SHALL）。今後の刻印先は Arc メインネット（チェーン ID `5042`）とし、チェーンに依存する値を複数の実装箇所へ固定で埋め込んではならない（MUST NOT）。

刻印の照会・署名・送信・結果の記録は同じチェーン設定に従わなければならない（SHALL）。送信の前に接続先のチェーン ID を照会し、設定したチェーン ID と一致しない場合は送信してはならない（MUST NOT）。

コントラクトのアドレスは別のチェーンでも同じ値になりうるため、アドレスの一致をチェーン ID の照合の代わりにしてはならない（MUST NOT）。

#### Scenario: 設定したチェーンへの送信

- **WHEN** 有効な未刻印の対象があり、接続先のチェーン ID が設定した `5042` と一致する
- **THEN** メインネットへ刻印が送信され、成功後の刻印の記録もチェーン ID `5042` を持つ

#### Scenario: 設定と接続先の不一致

- **WHEN** 接続先の RPC が返すチェーン ID が設定した `5042` と異なる
- **THEN** 刻印は送信されず、不一致が実行記録に残る

#### Scenario: 同じアドレスを持つテストネットへの誤接続

- **WHEN** 接続先のコントラクトアドレスが設定と同じでも、RPC がチェーン ID `5042002` を返す
- **THEN** 刻印は送信されず、チェーン ID の不一致として記録される

### Requirement: 開発データを引き継がないメインネットへの移行

システムは、切替え前に開発環境で生成したレコードと刻印の記録を削除し、メインネット運用へ引き継いではならない（MUST NOT）。移行前のデータの保存・復元は要求しない。これは一回限りの開発データ整理であり、移行後に保存するレコードと刻印の不変性は維持しなければならない（SHALL）。

切替えの作業中は、定期実行と手動再実行による収集・刻印を停止し、停止前から実行中の処理が終了してから削除しなければならない（SHALL）。メインネットに設定を揃えてから処理を再開しなければならない（SHALL）。

#### Scenario: 削除した開発データの刻印対象からの除外

- **WHEN** 旧開発データを削除してメインネットの刻印処理を再開する
- **THEN** 削除した旧レコードは刻印の対象にならず、メインネットに再刻印されない

#### Scenario: 切替え中の書込みの停止

- **WHEN** 旧開発データの削除とメインネットへの設定変更を行う
- **THEN** 定期実行と手動再実行による収集・刻印は行われず、旧データは書き戻されない

#### Scenario: 再開後の最初の実レコード

- **WHEN** 空のレコード保存先で最初の前日収集が成功し、その後の刻印の定期実行を行う
- **THEN** 前日のリビジョン 1 がメインネットに刻印され、それより古い開発期間の日は自動的に埋め戻されない

## MODIFIED Requirements

### Requirement: 署名鍵の扱い

システムは、刻印専用の署名鍵を用いなければならない（SHALL）。署名鍵は Worker のシークレットとしてのみ保持し、実行記録・生応答・刻印の結果に含めてはならない（MUST NOT）。

署名鍵・RPC の URL・コントラクトのアドレスのいずれかが未設定の場合、システムは刻印を行わず、未設定の項目名を実行記録に残さなければならない（SHALL）。この場合も収集は通常どおり行う。

刻印の鍵は実際の価値を持つ資産を扱う。運営者が指定した場合、決済の受取先と同じアドレスを使用できなければならない（SHALL）。年間運用分の資金確保をメインネットへの切替えの必須条件としてはならない（MUST NOT）。運営者は必要に応じて補充する。

#### Scenario: 署名鍵が未設定

- **WHEN** 署名鍵が設定されていない状態で日次実行を行う
- **THEN** レコードは保存され、刻印は行われず、未設定の項目名が刻印の実行記録に残る

#### Scenario: 実行記録への署名鍵の混入

- **WHEN** 刻印の実行記録を保存する
- **THEN** 記録に署名鍵の値は含まれない
