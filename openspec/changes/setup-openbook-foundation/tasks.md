## 2. 日次財務レコードの表現（financial-record）

- [ ] 2.1 10 進固定小数点の加減算・丸め（ROUND_HALF_UP、小数第 2 位）を `packages/shared` に実装する。端数を含む加算と丸めの単体テストが通ることを確認する
- [ ] 2.2 レコード・費用エントリ・収益エントリ・為替レートの型を定義する。金額が文字列で表現され、取得方式（`measured` / `derived` / `estimated`）が必須であることを型と実行時検証の両方で確認する
- [ ] 2.3 正準 JSON 直列化（RFC 8785 + 配列の並び順規則）を実装する。「項目の生成順序が異なる同一内容から同一バイト列が得られる」「費用エントリを異なる順序で与えても同一バイト列になる」「金額を最小桁だけ変えるとバイト列が変わる」の 3 テストが通ることを確認する
- [ ] 2.4 レコードのバリデーション（必須項目、日付形式、ISO 4217 通貨コード、取得方式、算出根拠の有無）を実装する。仕様の各拒否シナリオに対応するテストが通ることを確認する
- [ ] 2.5 集計値の再計算検証を実装する。明細と一致しない `totals` を持つレコードが拒否されるテストが通ることを確認する
- [ ] 2.6 `schemaVersion` を定数として定義し、レコード生成時に必ず付与する。バージョンを持たないレコードが拒否されるテストが通ることを確認する

## 3. JPY への通貨換算（currency-conversion）

- [ ] 3.1 Frankfurter（`api.frankfurter.dev`）から対象日の USD/JPY レートを取得する処理を実装する。応答をモックした単体テストで、レート値と実際の公表日を取得できることを確認する
- [ ] 3.2 市場休場日の扱いを実装する。対象日と公表日が異なる場合に、適用した公表日がレコードに記録されるテストが通ることを確認する
- [ ] 3.3 外貨建て金額を JPY へ換算する処理を実装する。原通貨・原金額・適用レート・換算後金額がすべて保持され、1 レコード内で同一通貨ペアに同一レートが適用されるテストが通ることを確認する
- [ ] 3.4 レート取得失敗時の扱いを実装する。レコードが `provisional` となり、換算値を持たず、過去に取得したレートが流用されないテストが通ることを確認する

## 4. レコードの保存と取得（snapshot-storage）

- [ ] 4.1 対象日とリビジョン番号からキーを導出する処理を実装する。`records/2026-09-07/001.json` が得られる単体テストが通ることを確認する
- [ ] 4.2 条件付き書き込みによる保存を実装する。「新規キーへの書き込みが成功する」「既存キーへの書き込みが失敗し、既存内容が変化しない」の 2 テストが通ることを確認する（[design.md - 決定 2](design.md) の注意点に従い、期待どおり動作しない場合は事前確認と書き込み後照合の併用へ切り替える）
- [ ] 4.3 訂正リビジョンの追加を実装する。置き換え対象と訂正理由を含む新リビジョンが追加され、過去リビジョンが引き続き取得できるテストと、訂正理由なしの保存が拒否されるテストが通ることを確認する
- [ ] 4.4 レコード取得（最新リビジョン・リビジョン指定・期間指定・不在日）を実装する。保存されたバイト列がそのまま返り、再直列化されていないことをバイト列比較のテストで確認する
- [ ] 4.5 生のプロバイダ応答を `raw/{対象日}/{取得元}.json` へ保存する処理を実装する。認証情報が含まれないことを検証するテストが通ることを確認する
- [ ] 4.6 保存前にバリデーションを実行する経路を実装する。不正なレコードの保存要求後にストレージの状態が変化しないテストが通ることを確認する

## 5. 日次バッチ実行基盤（daily-batch）

- [ ] 5.1 収集ソースのインタフェースとレジストリを実装する。ソース 0 件で実行したときに空レコードが生成されるテストと、複数ソースの結果が 1 レコードに統合されるテストが通ることを確認する
- [ ] 5.2 Cron Triggers から前日を対象に実行する処理を実装する。スケジュール実行のハンドラが対象日を正しく算出するテストが通ることを確認する
- [ ] 5.3 部分失敗の扱いを実装する。「一部失敗時に成功分でレコードが生成され `provisional` となる」「全ソース失敗時にレコードが生成されない」の 2 テストが通ることを確認する
- [ ] 5.4 実行記録の保存を実装する。対象日・開始終了時刻・ソースごとの成否と失敗理由・生成リビジョンが記録されるテストが通ることを確認する
- [ ] 5.5 暫定値と確定値の判定、および猶予期間経過後の再収集による確定処理を実装する。「値が変化した場合に訂正リビジョンが追加され `finalized` になる」「変化しない場合にリビジョンが増えない」の 2 テストが通ることを確認する
- [ ] 5.6 再実行の冪等性を実装する。同一内容の再実行でリビジョンが増えないテストが通ることを確認する
- [ ] 5.7 手動再実行エンドポイントを共有シークレットの Bearer 認証つきで実装する。「認証済み要求で指定日の収集が実行される」「認証情報のない要求が拒否され収集が実行されない」の 2 テストが通ることを確認する
