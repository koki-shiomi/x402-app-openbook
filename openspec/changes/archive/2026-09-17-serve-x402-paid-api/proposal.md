## Why

日次レコードは 2026-09-08 から R2 に保存され、④で各日の最新リビジョンのハッシュを Arc テストネットへ刻印している。しかし現時点で外部に開いているのは `/health` と運営者専用の `/admin/rerun` だけで、**レコードのバイト列を第三者が取得する手段がない**。④で用意した検証手順書も、検証の起点となるバイト列を入手できないため実行できない。

本チェンジは、日次レコードを x402 による USDC 決済つきの有料 API として公開し、検証の前提である「公開物のバイト列」を第三者が入手できるようにする。⑥`build-public-dashboard` はこの API を利用者として叩く。

## What Changes

- **日次レコードを 1 日単位の有料エンドポイントとして公開する**。価格は 1 日あたり 0.10 USDC、決済は Arc テストネット上の USDC、x402 の `exact` スキームを用いる
- **検証可能性を鮮度より優先する**。返すのはチェーン上に刻印済みの最新リビジョンだけとする。保存済みだが未刻印の日は、支払いを求めずに刻印待ちであることを示して拒む
- **レコード本体は保存されたバイト列をそのまま返す**。刻印の情報（トランザクションのハッシュ・ブロック番号・コントラクトのアドレス・チェーン ID）は HTTP ヘッダで添える。本文に混ぜるとハッシュが変わり、検証が成立しない
- **取得可能な日付の一覧だけを無料で公開する**。日付とリビジョン番号のみで金額は含めない。利用者が存在しない日に支払うことを防ぎ、⑥が支払いなしで骨格を描けるようにする
- **支払いの明細を記録する**。時刻・対象日・金額・支払い元アドレス・トランザクションのハッシュを保存する。日次レコードの収益には含めない。テストネットの USDC には経済的価値がなく、収益として公開すると実態を誤らせる
- **存在しない日は支払いを求めずに拒む**。稼働開始前の日や未来の日に対して、利用者が無駄な支払いをしないようにする

## Capabilities

### New Capabilities

- `paid-record-api`: 日次レコードを公開するエンドポイントの振る舞い。課金の対象と単位、返す内容、刻印情報の添え方、存在しない日と未刻印の日の扱い、無料で公開する範囲
- `x402-payment`: x402 による決済の成立。プロトコルのバージョンとスキーム、決済のネットワークと資産、価格と受取先、facilitator の利用、支払いの明細の記録

### Modified Capabilities

なし。既存の仕様が定める収集・保存・刻印の振る舞いは変えない。

## Impact

- **コード**: `apps/api/src/index.ts`（公開エンドポイントの追加）、`apps/api/src/api/`（新規。一覧・レコードの取得・刻印情報の付与）、`apps/api/src/payment/`（新規。x402 の設定と支払いの明細）
- **依存**: `@x402/hono`・`@x402/core`・`@x402/evm`（いずれも 2.26.0 系）。`@x402/core` は `zod` のみに依存し Node 固有の API を使わないため Workers で動作する
- **シークレット**: facilitator の URL と受取アドレスを追加する。受取アドレスは刻印用の EOA と兼用するため、新たな秘密鍵は増えない
- **保存済みデータ**: 移行は不要。既存の `records/` と `anchors/` をそのまま読む。支払いの明細は新しい接頭辞に保存する
- **公開**: 日次レコードのバイト列が初めて外部から取得可能になる。④の検証手順書が第三者にも実行できるようになる
- **⑥build-public-dashboard**: 本チェンジの API を唯一の取得元とする。一覧は無料で読めるが、金額を表示するには支払いが必要になる
- **④anchor-daily-hash-on-arc**: 刻印済みのリビジョンだけを公開するため、`openspec/config.yaml` に記録した「API が返すすべての情報は検証可能であることを鮮度より優先する」方針が、本チェンジで実際の振る舞いになる
