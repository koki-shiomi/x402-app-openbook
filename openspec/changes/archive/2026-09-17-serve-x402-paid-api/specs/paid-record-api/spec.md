## Purpose

日次財務レコードを外部へ公開するエンドポイントの振る舞いを定める。公開したバイト列が常にチェーン上の刻印と照合できる状態を保ち、利用者が取得できない日に支払うことを防ぐ。

## ADDED Requirements

### Requirement: 日次レコードの取得

システムは、対象日を指定して当該日の日次レコードを取得できるエンドポイントを提供しなければならない（SHALL）。返す本文は、保存されているバイト列そのものでなければならない（SHALL）。解析して直列化し直してはならない（MUST NOT）。

返すのは当該日の最新リビジョンのみとする。過去のリビジョンを取得する手段を提供してはならない（MUST NOT）。過去のリビジョンは訂正前の値であり、現行の値と取り違えられる恐れがある。

再直列化すると、公開されるバイト列がハッシュの対象と一致しなくなり、検証が成立しない。

#### Scenario: 刻印済みの日の取得

- **WHEN** 支払いを伴う要求で、刻印済みの最新リビジョンがある対象日を指定する
- **THEN** 保存されているバイト列がそのまま返る

#### Scenario: 取得したバイト列の検証

- **WHEN** 取得したバイト列の SHA-256 を、チェーン上の当該日と当該リビジョンの刻印と照合する
- **THEN** 一致する

#### Scenario: 過去のリビジョンの指定

- **WHEN** 最新ではないリビジョンを指定して取得を試みる
- **THEN** リビジョンの指定は受け付けられず、最新リビジョン以外を取得する手段はない

### Requirement: 刻印情報の添付

システムは、日次レコードを返すとき、その刻印の情報を本文とは別に添えなければならない（SHALL）。本文へ埋め込んではならない（MUST NOT）。添える内容は、リビジョン番号・刻印したハッシュ・チェーン ID・コントラクトのアドレス・トランザクションのハッシュ・ブロック番号とする。

本文へ混ぜるとバイト列が変わり、ハッシュが刻印と一致しなくなる。

#### Scenario: 刻印情報の取得

- **WHEN** 刻印済みの日を取得する
- **THEN** 本文とは別に、リビジョン番号・ハッシュ・チェーン ID・コントラクトのアドレス・トランザクションのハッシュ・ブロック番号が得られる

#### Scenario: 本文の不変性

- **WHEN** 刻印情報を添えて日次レコードを返す
- **THEN** 本文のバイト列は、刻印情報を添えない場合と同一である

### Requirement: 未刻印の日の扱い

システムは、レコードは存在するが最新リビジョンが未刻印である日について、支払いを求めてはならない（MUST NOT）。刻印待ちであることと対象日を示して拒まなければならない（SHALL）。存在しない日と区別できる応答としなければならない（SHALL）。

公開したすべての情報が検証可能である状態を、鮮度より優先するためである。未刻印の状態は、保存から刻印までの短い間と、刻印が失敗してから次の実行までの間に生じる。

#### Scenario: 刻印待ちの日の要求

- **WHEN** レコードは存在するが最新リビジョンが未刻印である日を要求する
- **THEN** 支払いを求められず、刻印待ちである旨と対象日を含む応答が返る

#### Scenario: 刻印後の再要求

- **WHEN** 刻印待ちだった日が刻印された後に、同じ日を要求する
- **THEN** 通常どおり支払いを求められ、支払い後にレコードを取得できる

### Requirement: 存在しない日の扱い

システムは、レコードが存在しない対象日について、支払いを求めてはならない（MUST NOT）。存在しないことを示して拒まなければならない（SHALL）。

稼働開始前の日・未来の日・収集に失敗してレコードを作らなかった日が該当する。支払いを求めてから存在しないと返すと、利用者が取得できないものに支払うことになる。

#### Scenario: 稼働開始前の日の要求

- **WHEN** レコードが存在しない対象日を要求する
- **THEN** 支払いを求められず、存在しない旨の応答が返る

#### Scenario: 対象日の形式が不正な要求

- **WHEN** 実在しない暦日や形式の異なる値を対象日として要求する
- **THEN** 支払いを求められず、要求が不正である旨の応答が返る

### Requirement: 取得可能な日付の一覧

システムは、取得可能な対象日の一覧を支払いなしで提供しなければならない（SHALL）。一覧には対象日とそのリビジョン番号のみを含め、金額を含めてはならない（MUST NOT）。

一覧の対象は、レコードが存在し、かつ最新リビジョンが刻印済みの日とする。取得できない日を一覧に含めてはならない（MUST NOT）。

金額を含めないのは、一覧が有料の対象である日次レコードの代替にならないようにするためである。一覧を無料にするのは、利用者が存在しない日や刻印待ちの日に支払うことを防ぎ、取得する前に対象を選べるようにするためである。

#### Scenario: 一覧の取得

- **WHEN** 支払いを伴わずに一覧を要求する
- **THEN** 取得可能な対象日とそのリビジョン番号が返り、金額は含まれない

#### Scenario: 未刻印の日の除外

- **WHEN** レコードは存在するが未刻印の日がある状態で一覧を要求する
- **THEN** その日は一覧に含まれない

### Requirement: 運営者向けエンドポイントの区別

システムは、運営者専用のエンドポイント（手動再実行）と稼働確認用のエンドポイントに、支払いを求めてはならない（MUST NOT）。これらを利用者向けの API ドキュメントに含めてはならない（MUST NOT）。

手動再実行は共有シークレットによる認証で保護されており、利用者が呼ぶものではない。稼働確認は金額を返さない。

#### Scenario: 運営者向けエンドポイントへの要求

- **WHEN** 手動再実行または稼働確認のエンドポイントを要求する
- **THEN** 支払いは求められない

#### Scenario: API ドキュメントの範囲

- **WHEN** 利用者向けの API ドキュメントを参照する
- **THEN** 手動再実行と稼働確認のエンドポイントは記載されていない
