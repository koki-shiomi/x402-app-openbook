## ADDED Requirements

### Requirement: Supabase 費用の組織プラン確認による裏付け

システムは、Supabase の組織のプランを取得し、確認結果を算出根拠として記録しなければならない（SHALL）。プランが無料である場合に限り、金額 0 の費用エントリを取得方式 `estimated` として記録しなければならない（SHALL）。プランが無料でない場合は、0 円として記録せず、費用が発生している旨を欠測として記録しなければならない（SHALL）。

プロジェクトごとの課金アドオンを確認してはならない（MUST NOT）。課金は組織を単位として行われ、課金アドオンは有料プランのプロジェクトにのみ適用できる。組織のプランが無料であることを確認できれば、アドオンによる費用は生じない。プロジェクトごとの確認は、プロジェクト数に応じて問い合わせ回数が変わるため、宣言した回数と実際を一致させられない。

#### Scenario: 無料プラン

- **WHEN** 組織のプランが無料である
- **THEN** 金額 0 の費用エントリが作成され、プラン名が算出根拠に含まれる

#### Scenario: 無料ではないプラン

- **WHEN** 組織のプランが無料ではない
- **THEN** 0 円として記録せず、費用が発生している旨を欠測として記録する

#### Scenario: プロジェクト数の異なる組織

- **WHEN** 組織のプロジェクト数が異なる状態でそれぞれ取得する
- **THEN** いずれの場合も外部への問い合わせ回数は同じである

## MODIFIED Requirements

### Requirement: 現在の状態しか返さない提供元の遡及可能期間

システムは、現在の契約状態しか取得できない提供元（Supabase の組織のプラン、Cloudflare のサブスクリプション）について、前日より前の対象日を取得できないものとして宣言しなければならない（SHALL）。

これらの API は過去の時点を指定する手段を持たない。過去日の再収集に現在の状態を適用すると、その日の実態と異なる判定になる。たとえば後から有料の契約を追加すると、無料だった過去日まで欠測に置き換わる。

#### Scenario: 前日を対象とした取得

- **WHEN** 前日を対象に取得する
- **THEN** 実行時点の状態を根拠として取得される

#### Scenario: 前日より前の対象日

- **WHEN** 前日より前の対象日を再収集する
- **THEN** 取得は試みられず、既存の値が維持される

## REMOVED Requirements

### Requirement: Supabase 費用のプラン確認による裏付け

**Reason**: 課金アドオンの確認をやめるため、シナリオの前提（すべてのプロジェクトでアドオンが空であること）が成り立たなくなる。要件の名称とシナリオ名がいずれも実際の確認内容と食い違うため、置き換える

**Migration**: 「Supabase 費用の組織プラン確認による裏付け」が置き換える。判定の結果は変わらない。組織のプランが無料なら金額 0 の費用エントリ、無料でなければ欠測となる。算出根拠からアドオンの確認結果が消え、プラン名のみになる
